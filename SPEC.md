# Statehouse — Legislation Search & Collaborative Annotation

Full-stack TypeScript platform over state legislation: hybrid semantic search backed by pgvector, bill-version diffing, and real-time collaborative annotations.

## Specification

Build a monorepo (npm workspaces, package.json and package-lock.json at the repo root, NO pyproject.toml)
with a Next.js (App Router) + TypeScript web app and a Node/TypeScript API.

1. Ingestion (Node script): download bills + all text versions, normalize into Postgres tables
   (bills, bill_versions, sponsors, actions). Idempotent re-runs keyed on bill id + version id.
2. Search: chunk bill text; embed chunks with a local embedding model (@xenova/transformers,
   all-MiniLM-L6-v2) stored in Postgres via pgvector; hybrid ranking = Postgres full-text (ts_rank) +
   vector cosine combined with reciprocal rank fusion. Filters: session, status, sponsor, subject.
   Endpoint GET /api/search returns ranked bills with highlighted snippets.
3. Version diffing: word-level diff between any two versions of a bill (e.g. introduced vs amended),
   rendered side-by-side and inline with insertions/deletions highlighted.
4. Collaborative annotations: users highlight a passage and attach a note; annotations sync live
   across open browser tabs via WebSockets (ws or Socket.IO), persist in Postgres, anchor to text
   offsets in a specific version, and are re-anchored or flagged when a newer version changes the passage.
5. UI: search page with instant results (debounced), bill detail page with version selector, diff view,
   annotation sidebar; a small Recharts chart of bill activity over time. Shared design tokens (CSS
   variables) and Storybook stories for the core components (SearchBar, ResultCard, DiffView, AnnotationPanel).
6. Performance: a benchmark script runs 200 queries against the loaded dataset and writes
   results/search_latency.json (p50/p95 ms, corpus size). Report only those numbers.
7. Ops: docker-compose (postgres with pgvector + app), structured JSON logging, a feature flag
   (env var) gating the semantic half of the search, GitHub Actions CI running lint, typecheck and tests.
8. Tests (`npm test` must run fully offline with no Docker): use @electric-sql/pglite with the vector
   extension (or an in-memory fake repository) and recorded fixture bills; cover ingestion idempotency,
   RRF ranking, diffing, annotation re-anchoring, and the WebSocket broadcast logic.

## Data
- California Legislative Information bill text (https://leginfo.legislature.ca.gov/ and the public
  "pubinfo" download at https://downloads.leginfo.legislature.ca.gov/), public government records.
  Ingest a few hundred bills from one session, including bills with 2+ amended versions.
- Fallback if the CA download format is impractical: GovInfo BILLS bulk XML (https://www.govinfo.gov/bulkdata/BILLS),
  US government work, public domain. State which source was used in the README.
- Commit only small fixtures (<5MB); everything else is downloaded by a script.
